# P2.1 Contributor Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new contributor clones the repository, reads the README, runs `npm run setup`, and opens Pi with Superpowers available at a recorded revision.

**Architecture:** One Node ESM setup script with pure, injectable decision logic (settings parsing, action selection, command construction) and a thin subprocess runner; a contributor README; a revision/setup record. All tests are model-, network- and subprocess-free: subprocesses are fakes, settings live in temporary directories.

**Tech Stack:** Node >= 20 (`node:test`, `node:child_process`, `node:fs`), npm, uv, Pi git packages (`pi install git:…@<commit>`).

**Spec:** `docs/superpowers/specs/2026-11-18-p2.1-contributor-setup-design.md`

## Global Constraints

- Branch `p2.1/contributor-setup`, stacked on `p1.2/vocabulary` (`015c93d`); do not touch `main` or the P1.2 branch.
- Superpowers pin: source `git:github.com/obra/superpowers`, commit `bb92a77741419a4ab5f06e711a283343f1ada0c3` (`v6.1.1-56-gbb92a77`, 2026-10-09). Never a floating ref.
- Pi config directory: `$PI_CODING_AGENT_DIR` if set, else `~/.pi/agent`; settings file is `settings.json` inside it.
- `npm test` and `uv run pytest` stay model-, network- and subprocess-free; the real script is never executed by a default test.
- Setup changes user-level Pi configuration; a different or unpinned existing Superpowers entry is never rewritten without an explicit `--yes`.
- Plain Markdown docs; `ROADMAP.md` cells stay within the `docs/sdd.md` caps; no edits to `docs/sdd.md` or `docs/provenance/`.
- No root `AGENTS.md`, wrapper skill, `BACKLOG.md`, gates or runtime code in this cycle; those are P2.2–P2.6.

## Review Focus

- A rig with an **unpinned** Superpowers entry (the common case today): setup must refuse without `--yes`, not silently pin it. Pinned by Task 1's `decideAction` tests.
- **Missing `uv` or `pi`**: setup fails before `npm ci`, naming the missing tool. Pinned by Task 1's tool-check ordering test.
- **A failing subprocess** (`npm ci`, `uv sync`, `pi install`): setup exits nonzero and prints no success summary. Pinned by Task 1's failure-propagation test.
- **Fresh clone with no `node_modules`**: `npm run setup` must work as the first command. Proven by Task 4's fresh-clone run.
- **Documentation drift**: the recorded revision in `docs/superpowers/setup.md` must equal the script's pin. Pinned by Task 2's consistency test.

### Task 1: Setup script and npm wiring

**Files:**
- Create: `scripts/setup.mjs`
- Test: `tests/setup.test.mjs`
- Modify: `package.json` (add `"setup": "node scripts/setup.mjs"`)

**Interfaces:**
- Consumes: nothing outside Node's standard library.
- Produces: `SUPERPOWERS` (`{ source, commit, describe }`, frozen), `findSuperpowersEntry(settings)`, `decideAction(entry, { yes })`, `installArgs()`, `runSetup({ exec, log, env, yes })`. Task 2's consistency test reads `SUPERPOWERS.commit`.

- [ ] **Step 1: Write the failing tests**

In `tests/setup.test.mjs`, import from `../scripts/setup.mjs` and cover:

- `findSuperpowersEntry`: `{}` and `{ packages: [] }` → `{ status: "absent" }`; `{ packages: ["git:github.com/obra/superpowers"] }` → `{ status: "unpinned" }`; the same string with `@<40-hex>` → `{ status: "pinned", ref }`; unrelated packages (npm, other git URLs) are ignored, including `git:github.com/obra/superpowers-fork`.
- `decideAction`: absent → `install`; pinned at `SUPERPOWERS.commit` → `none`; pinned at another commit, or unpinned, → `refuse` without `yes` and `change` with `yes`.
- `installArgs()` returns `["install", "git:github.com/obra/superpowers@bb92a77741419a4ab5f06e711a283343f1ada0c3"]`.
- `runSetup` with a fake `exec` recording calls: missing `uv` or `pi` → throws before any `npm ci`; success path calls, in order, tool checks, `npm ci`, `uv sync`, then `pi install …` only when the action is not `none`; a nonzero fake `exec` result aborts with a nonzero-outcome error and no success log; `refuse` aborts before any `pi install` and its message names `--yes`.
- Settings are read via `runSetup`'s `env` (`PI_CODING_AGENT_DIR` pointing at a `mkdtemp` directory), so no test touches the real `~/.pi/agent`.

- [ ] **Step 2: Run the tests and confirm they fail**

Run: `node --test tests/setup.test.mjs`
Expected: FAIL — `Cannot find module '../scripts/setup.mjs'`.

- [ ] **Step 3: Implement `scripts/setup.mjs`**

Pure functions plus a thin runner. `findSuperpowersEntry` matches array entries by repository URL with any `@ref` stripped. `runSetup` checks tools (`pi --version`, `uv --version`), runs `npm ci` then `uv sync` in the repository root, reads settings (missing file means absent), applies `decideAction`, runs `pi install` for `install`/`change`, and logs each step plus a final summary only on success. Default `exec` uses `spawnSync` with stdio inherited; the CLI entry parses `--yes`, maps failures to exit code 1, and runs only when invoked directly.

- [ ] **Step 4: Run the tests and confirm they pass**

Run: `node --test tests/setup.test.mjs`
Expected: PASS, all tests.

- [ ] **Step 5: Wire the npm script and run the default suites**

Add `"setup": "node scripts/setup.mjs"` to `package.json`. Run `npm test` and `uv run pytest`.
Expected: 7 existing Node tests plus the new ones pass; 2 Python tests pass.

- [ ] **Step 6: Commit**

```bash
git add scripts/setup.mjs tests/setup.test.mjs package.json
git commit -m "feat: add contributor setup script with pinned Superpowers"
```
