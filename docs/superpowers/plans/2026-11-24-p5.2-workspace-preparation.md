# P5.2 Workspace Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Written in the same session as the code.** The failing-first runs it cites are
> the ones that happened, recorded in order; the plan was not reconstructed from
> memory after the fact.

**Goal:** Each task in a job gets a workspace built from its fixture — base, then
overlay, then deletions — with its prompt beside it and a `trial.json` that says
`prepared` and cannot be mistaken for a result.

**Architecture:** Two modules and a CLI step. `workspace.py` copies and edits files;
`trial.py` owns the closed status set and the atomic replace. Nothing spawns a
process or opens a socket, so this cycle stays in the fast default suite.

**Tech Stack:** Python 3.12+ standard library (`shutil`, `json`, `pathlib`), `pytest`.

**Spec:** `docs/superpowers/specs/2026-11-24-p5.0-eval-cli-design.md`
**Domain:** [`docs/domain.md`](../../domain.md) — the trial record and its boundaries.

## Global Constraints

- Branch `p5.2/workspace-preparation`, stacked on `p5.1/eval-resolution`.
- No process and no socket. `subprocess` does not appear in this cycle's code.
- The prompt is written **beside** the workspace, never inside it: a file in the
  tree is one the agent can read and grading must ignore.
- Re-running preparation replaces the workspace, so a file from an earlier attempt
  cannot be graded as part of this one.
- `trial.json` is written before the workspace is prepared and replaced atomically
  at every boundary, so a preparation failure leaves a `prepared` record rather
  than a workspace with nothing that explains it.

## Review Focus

- **A prompt inside the workspace.** Pinned by a test asserting `prompt.txt` is in
  the trial directory and absent from `workspace/`.
- **A status set that drifts.** `write_trial` refuses any status outside the closed
  five, so a later cycle cannot invent `complete`.
- **A partial trial that looks finished.** A test asserts `prepared` carries no
  `verdict` and no `score`, and that `final()` is false until `graded` or `stopped`.
- **A stale base file surviving a second attempt.** Pinned by preparing twice with
  a leftover file planted between.

  `satyrn_pi.workspace`, then 7 tests; the same for `satyrn_pi.trial`, then 9 tests;
  then 2 CLI tests failing on an empty trial list before the wiring.
- **A design error caught by writing the tests honestly**: the first
  implementation put `prompt.txt` inside the workspace. Two tests were too weak to
  see it, so they were replaced with ones that pin the prompt's location and the
  workspace path, and the code moved the prompt beside the tree.
- `write_trial` refuses `invented`, `done` and `complete`; `prepared` and
  `session-ended` are not final; a trial left at `prepared` is never written as
  `failed`.
- A second preparation with a planted `leftover.py` removes it, so a stale file
  cannot reach grading.
- No process and no socket: the default suites are unchanged and the tripwire needs
  no exemption for this cycle.

## Review (2026-11-24)

Reviewed by Kimi K3.1 against the spec, `docs/domain.md`, the glossary and the
repository's test rules. Five findings, all corrected:

- **P0, fixed:** a `deletions.txt` entry could unlink a file outside the workspace
  — absolute entries discarded the destination, and `../` escaped it. Deletions are
  now resolved and refused unless contained by the workspace, with regression tests
  for both shapes and a sentinel file that must survive.
- **P1, fixed:** `write_trial` validated only the status, so a non-final record
  could carry `verdict` and `score`, including by inheritance from an earlier final
  record. It now refuses result fields on any non-final status.
- **P1, fixed:** the trial record omitted the pinned model that `docs/domain.md`
  requires preparation to record. Each `trial.json` now carries it, and a test
  asserts it matches `job.json`.
- **P1, fixed:** `test_a_prepared_trial_carries_no_verdict_and_no_score` passed with
  the invariant broken, because it never supplied the fields. Replaced with cases
  that do, for every non-final status.
- **P2, fixed:** the guide promised status 2 wrote nothing at all, while a
  preparation failure leaves partial records. The guide now distinguishes a stop
  before the job directory from one after it. Its claim that P5.2 records the
  session was also wrong, and now says P5.3.

Pytest 77 → 85 on the fixes.
