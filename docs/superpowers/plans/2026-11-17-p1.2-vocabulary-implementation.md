# P1.2 Vocabulary and Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Document Satyrn Pi's architecture and canonical vocabulary, including the Vanilla/Base desk walk and the agreed run-record boundaries.

**Architecture:** Add one onboarding-oriented domain map and revise the existing glossary as a short definitional dictionary. Update the active P1.2 plan with the decisions and ambiguity record; do not add runtime code or settle the numeric budget.

**Tech Stack:** Markdown, Python 3 standard-library validation snippets, Node's existing repository-weight test, pytest.

**Spec:** `docs/superpowers/plans/2026-11-16-vocabulary.md` plus the P1.2 decisions approved during brainstorming on 2026-11-17.

## Global Constraints

- `docs/domain.md` is the map of responsibilities and seams; `docs/glossary.md` is the dictionary of terms.
- Both documents have exactly four short introductory source lines immediately below their main heading.
- Domain prose cites glossary terms rather than redefining them; glossary entries contain no architectural imperatives.
- The glossary contains ten `###` entries: Agent, Vanilla, Base, Remedy, Preset, Eval suite, Task, Job, Trial, Trajectory.
- Agent is the genus of Vanilla, Base, Easy, Medium and Hard; agents are not presets or experimental arms.
- Retain Harbor's Agent, Task, Job, Trial and Trajectory where they identify real boundaries; map Dataset to Eval suite and Verifier to Grader.
- Vanilla exposes the expected failures of ordinary Pi with a small model; Base supplies the minimum research environment for investigating pathologies and remedies.
- Redispatch keeps one session ID within one trial; incremental `trial.json` writes preserve citable partial evidence without implying completion or a score.
- Do not choose the numeric glossary budget; Nicola, Ben and the implementers own that agreement.
- Do not add runtime code, detailed CLI/schema design, or claims that planned components already exist.
- Leave `main` and the P1.1 branch untouched; all work stays on `p1.2/vocabulary`.

## Review Focus

- A reader could equate Vanilla with Base because Base's preset starts empty; Task 1 defines their kinds and Task 3 records their different research purposes.
- A reader could confuse agent, model, preset and arm; Task 1 checks the genus and Task 2 explains the independent suite/preset choices.
- A reader could confuse job, trial and Pi session; Task 2 checks the complete lifecycle and the single-session-ID redispatch decision.
- An interrupted attempt could look complete or scored; Task 2 checks incremental records and the absence of invented verdicts.
- Planned architecture could be mistaken for current code; Task 2 labels future locations and Task 3 reviews the diff against the P1.1 skeleton.
