# P4.2 Reproduce the Reference Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Written before it was run.** This plan is the step list P4.3 turns into prose.
> It is committed before execution so that a step the walk changes is visible as a
> change rather than remembered as an intention.

**Goal:** The pinned build and the pinned weights run together on this machine and
answer a request, having been fetched and verified from a state that had neither —
and every step a reader will follow is a step this cycle actually ran.

**Architecture:** A private prefix for the build, a fresh weights file, a digest
check before anything executes, the documented command, one chat completion, and
a transcript. The observed footprint goes into the P4.1 card; the walk goes into
the plan's evidence.

**Tech Stack:** `curl`, `shasum -a 256`, `tar`, `llama-server` b12066, `curl` for
the OpenAI-compatible endpoint, `ps`/`footprint` for the observation.

**Spec:** `docs/superpowers/specs/2026-11-21-p4.0-getting-started-design.md`
**Card:** `docs/superpowers/research/2026-11-21-reference-host-card.md`

## Global Constraints

- Branch `p4.2/reproduce-reference`, stacked on `p4.1/reference-host-card`; one
  pull request based on that branch.
- The build lives in `~/.local/share/satyrn-llama/b12066/`, beside nothing. The
  weights live in `~/models/`, beside the two quants that are **not** the subject.
- Homebrew's `llama-server` (build 12110) stays installed and is never invoked:
  every command names the extracted binary by absolute path.
- Digests are checked **before** the binary runs or the model loads. A digest
  checked after a run proves nothing about the run.
- Nothing is installed system-wide, nothing is put on `PATH`, and no file outside
  the two directories above is created.
- The server binds `127.0.0.1:8001` only, and stops at the end of the walk.

## Review Focus

- **A response from the wrong server.** Homebrew's 12110 answers on the same port
  if it is already running. Pinned by the startup log's build number and model
  path, and by the port being free before the walk starts.
- **A digest that proves nothing.** Both digests are compared to the card before
  extraction and before load; the comparison is in the transcript.
- **A step nobody ran.** Every command in this plan is one the walk executed, in
  order; a step added later is added as a change with its own output.
- **A memory number that means the wrong thing.** The startup allocation the
  server logs is recorded separately from the process's observed peak footprint,
  and the card labels which is which.

### Task 1: Prove the port is free and the digests match

**Files:** none — the transcript is the artifact.

**Interfaces:**
- Consumes: the card's two digests, the two downloads.
- Produces: byte-identical files, or a stopped cycle.

- [x] **Step 1: Confirm nothing is already on the port**

```sh
lsof -nP -iTCP:8001 -sTCP:LISTEN
```

**Divergence, 2026-11-21:** the port was already taken by `omlx-server` (PID
81553, started 2026-11-20 17:18), which serves twelve MLX models including
`Mellum2.1-12B-A2.5B-Thinking-6bit` under `/v1/models`. Nothing was killed: it is
the machine's day-to-day inference server, not this cycle's to stop. The walk
pauses here until Paul says whether the reference port is this cycle's to claim.

This is also the sharpest form of the risk this plan names: a request to
`127.0.0.1:8001` on this machine would have been answered by MLX at 6 bits, and
looked like a successful reproduction.

- [x] **Step 2: Check the build asset against the card**

Observed: `909053143be864f6b2c45b45e140575904fde163978d33cea53f30f318e09a19`,
16,548,566 bytes — matching the card.

- [x] **Step 3: Check the weights against the card**

### Task 2: Extract the build and confirm the flags

- [x] **Step 1: Extract into the private prefix**

```sh
~/.local/share/satyrn-llama/b12066/llama-b12066/llama-server --version
```

**Correction, 2026-11-21:** the archive nests as `llama-b12066/llama-server`, not

Observed: `version: 0.8.0-dev (build 12066, commit 713319e28)`, built with
AppleClang for Darwin arm64 — the build the card pins.

- [x] **Step 2: Read this build's own `--help`**

```sh
~/.local/share/satyrn-llama/b12066/llama-b12066/llama-server --help |
```

Observed: every flag the card's command uses exists. Three notes for the card:
`-fa` already defaults to `auto`, `-b` defaults to 2048 (the source passes 512),
and `--jinja` is default-enabled in this build — so the source's flags are
preserved rather than required.

### Task 3: Serve the pinned file

- [ ] **Step 1: Start the documented command and capture its log**

```sh
~/.local/share/satyrn-llama/b12066/llama-b12066/llama-server \
  -m ~/models/Mellum2.1-12B-A2.5B-Thinking-Q4_K_M.gguf \
  -a Mellum2.1-12B-A2.5B-Thinking --host 127.0.0.1 --port 8001 \
  -c 50000 -np 1 --jinja -fa auto -b 512 -ub 512 -ctk q8_0 -ctv q8_0 \
  > /tmp/p42-serve.log 2>&1 &
```

Expected: the log names the model path and reports the buffers it allocates —
model, KV cache and compute — which is the allocation the page will publish.

- [ ] **Step 2: Wait for readiness and read the log back**

```sh
until curl -sf http://127.0.0.1:8001/health; do sleep 2; done
grep -E "build|model|n_ctx|KV self|kv cache|buffer size" /tmp/p42-serve.log
```

Expected: `server is listening`, build 12066, the pinned model path, and the
allocation lines the card will quote.

### Task 4: Ask it something

- [ ] **Step 1: One request against the served alias**

```sh
curl -sS http://127.0.0.1:8001/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"Mellum2.1-12B-A2.5B-Thinking","messages":[{"role":"user","content":"In one sentence, what does a bounded coding worker do?"}],"max_tokens":256,"temperature":1.0,"top_p":0.95,"top_k":20}'
```

Expected: a JSON response with non-empty `choices[0].message.content`, whose
thinking trace or answer shows the model is Mellum, not a placeholder.

- [ ] **Step 2: Record the observation while it serves**

```sh
ps -o rss=,vsz= -p $(pgrep -f "b12066/llama-b12066/llama-server" | head -1)
/usr/bin/footprint -p $(pgrep -f "b12066/llama-b12066/llama-server" | head -1) 2>/dev/null | tail -5
```

Expected: a peak footprint for the process, recorded as observed on this machine
and labelled as such — not as a property of the model.
