# P4.0 Phase 4 Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase 4's single row becomes three stacked cycles whose shared calls are
settled once, so P4.1 can open on a reference configuration that is pinned rather
than guessed.

**Architecture:** One phase-4 spec carrying the shared decisions, three roadmap
rows, a changelog line, and one pull request. No runtime code, no site change, no
artifact fetched.

**Tech Stack:** The existing document gates: `npm test` (`doc-caps`,
`doc-lifecycle`, `published-pages`), `npm run check:docs`, `uv run pytest`.

**Spec:** `docs/superpowers/specs/2026-11-21-p4.0-getting-started-design.md`

## Global Constraints

- Branch `p4.0/phase-4-cycles`, cut from `origin/main` at `a951dc9`; it is the base
  of the phase-4 stack, not a stacked child.
- P4.1 branches from this branch; P4.2 from P4.1; P4.3 from P4.2. Each opens one
  pull request based on the branch before it, retargeted to `main` as its parent
  merges.
- This cycle changes documents only: no `src/`, no `extensions/`, no `zensical.toml`,
  no `tests/`, no artifact download.
- The spec stays inside its 150-line cap with a reviewer brief of at most 30
  lines, and every call in `## Decisions` keeps its attribution.
- Preserved paths (`docs/sdd.md`, `docs/provenance/`, archived plans) stay
  byte-for-byte.
- Rows P4.1–P4.3 stay `proposed`; nothing here claims a merge, a download or a
  running server.

## Review Focus

- **A phase spec read as three approved cycles.** The rows say what each cycle
  ships and each opens with its own plan; the spec decides only the audience,
  the platform, the promise and the pin. Pinned by reading the rows' status cells.
- **A cap met by deleting reasoning.** Trimming to 150 lines is where decisions
  get lost, so the Decisions list is checked against the brainstorm before the
  commit, not after. Pinned by listing the calls in the evidence section.
- **A site change smuggled in.** The published-set test and `zensical.toml` are
  untouched here; the third page arrives in P4.3. Pinned by the diff.
- **A pin that cannot be checked.** Every digest in the spec is quoted from the
  publisher's metadata; the spec says so and P4.1 re-quotes it into the card.
  Pinned by the two fetch commands recorded in the evidence.
