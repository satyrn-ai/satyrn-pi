# P4.3 Publish Getting Started Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The recorded walk becomes the site's third page, so a visitor who
arrives from a social post can reach a model that answers — and can tell that the
answer came from the build and file this repository pins.

**Architecture:** One page rendered from P4.2's transcript, a nav entry, and two
deliberate test edits: the published set grows to three, and a new check fails
when the page and the reference card disagree about a pin. No build, network or
subprocess joins the default suite.

**Tech Stack:** `node:test`, `scripts/reference-pins.mjs`, `scripts/published-pages.mjs`,
`uv run zensical build --strict --clean`.

**Spec:** `docs/superpowers/specs/2026-11-21-p4.0-getting-started-design.md`
**Sources:** the [card](../research/2026-11-21-reference-host-card.md) and
[P4.2's walk](2026-11-21-p4.2-reproduce-reference.md).

## Global Constraints

- Branch `p4.3/publish-getting-started`, stacked on `p4.2/reproduce-reference`;
  one pull request based on that branch.
- The page's promise is *run the subject model on your machine*. It does not
  promise a worker, and its closing section says the worker is unpublished.
- Paths on the page are placeholders and one line says so; the card keeps this
  machine's absolute paths.
- The two macOS failures and the occupied port are named where the reader meets
  them, not collected in a troubleshooting appendix.
- The page repeats the card's pins, and `tests/reference-pins.test.mjs` fails when
  they disagree. Nothing in the default suite may read the network or run a build.
- The published set grows to three pages deliberately: `zensical.toml`'s
  `exclude_docs` stays as it is, and the expectation in
  `tests/published-pages.test.mjs` is edited in this cycle.

## Review Focus

- **A digest on the page that nobody compares to anything.** Pinned by
  `reference-pins`: every full-length hex value and the declared build tag in the
  card must appear on the page.
- **A published set widened by accident.** The expectation is edited in the same
  commit as the page, and the fixture tests that prove exclusion still fail on a
  planted fourth page. Pinned by `published-pages`.
- **A page that teaches "it answered" as verification.** Every check on the page
  names the build number or the model path first, because a different Mellum on
  the same port answers convincingly. Pinned by the page's section 4.
- **Prose that is not what ran.** Each numbered step corresponds to a step in
  P4.2's evidence, including the corrections it found.
