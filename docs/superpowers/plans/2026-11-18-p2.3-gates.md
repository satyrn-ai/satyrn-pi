# P2.3 Cap, Lifecycle and Evidence Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The document budgets, plan lifecycle and evidence wording are enforced by model-free checks in the default suite.

**Architecture:** One constants module, one checker module of pure functions over document text, three test files, and a thin CLI behind `npm run check:docs`. Repository scans use filesystem reads only; fixtures are generated in temp directories.

**Tech Stack:** Node >= 20 (`node:test`, `node:fs`, `node:path`), npm, existing `uv run pytest`.

**Spec:** `docs/superpowers/specs/2026-11-18-p2.3-gates-design.md`

## Global Constraints

- Branch `p2.3/gates`, stacked on `p2.2/rules-index`; one PR into that branch.
- `docs/sdd.md`, `docs/provenance/` and archived plans stay byte-for-byte.
- Default suites stay model-, network- and subprocess-free; checks read files only.
- Budgets: spec 150, plan 250, reviewer brief 30, `AGENTS.md` 80, roadmap 400, Ships/Excludes 900 chars, Status 1,000, backlog entry 1,200, plan fenced 25%.
- Wording scan is `docs/superpowers/research/**` only; `n\s*=\s*1`, never `n >= 1`; whole-word `null`/`void`/`separated`, case-insensitive, same `##` section.
- Corrections: P1.2's plan gets front matter; P2.1's spec gets a reviewer brief.
- Every archived plan needs a terminal `## Result`; the archived P1.1 plan already has one.

## Review Focus

- **Empty backlog or missing directories**: checks must return no findings, not throw. Pinned by the empty-backlog and absent-directory tests.
- **Fixtures leaking into repository scans**: all fixtures live in temp directories, never under the repo. Pinned by the repository scans returning `[]` after the fixture tests.
- **An archive bypassing the Result rule**: every archive path, including the P1.1 path, fails without a terminal `## Result`. Pinned by the archive tests.
- **`n >= 1` misread as `n = 1`**: the regex excludes an operator between `n` and `=`. Pinned by the wording test.
- **Checks mutating documents or spawning processes**: they return findings only. Pinned by tests that assert file contents are unchanged and by the imports used.
