# I.3 Stack Re-cut Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the phase-5 stack as four fresh requests — #23 rebased onto
`main` and merged, then P5.1–P5.4 cut from the surviving commits, each carrying
only its own cycle, with findings 2–5 fixed inside the cycle that owns them.

**Architecture:** History moves; behaviour does not. Every surviving commit is
cherry-picked in its original order, so each branch is the diff of one cycle.
Findings 4–5 land in P5.1 (resolution and records) and 2–3 in P5.3 (the session
boundary), each with a failing-first unit test through the injected spawner or
argv builder. The old requests close with pointers; no reviewed branch is
force-pushed except #23's own rebase.

**Tech Stack:** `git` (cherry-pick, range-diff), `gh`, `pytest`, `node:test`, `uv`, `zensical`.

**Spec:** `docs/superpowers/specs/2026-11-26-integration-phase-design.md`

## Preconditions

- #30 (I.1) is merged, so the hold and the P4.5 rows are on `main`. #31 (I.2) is independent.
- This plan is approved and merged on the documentation rule: green check plus Paul's authorisation.
- No cut starts before both. Run `git worktree list` first: a branch already checked out is used there or its worktree removed, never checked out twice.

## Global Constraints

- Commits are located by subject and proven reachable; remembered SHAs are not trusted. The orphans (`bfbf56d`, `5892423`, `cd5c35b`) stay dead.
- New branches end in `-recut`. The old four are closed, never force-pushed or deleted, so their review record stays readable.
- #23 is the only branch rebased in place; its push is `--force-with-lease`.
- One request per cycle: P5.1 against `main`, then each cycle against its parent. Nicola is assigned; Andre and Ben are mentioned for their lanes.
- Nothing merges without Nicola's approval. I.3 merges only #23; P5.1–P5.4 land in I.4. Paul or an agent clicks the merge.
- Default suites stay model-, network- and subprocess-free; every new test uses the fake spawner, fake probes or argv builder.
- The five gates are `npm test`, `uv run pytest`, `npm run check:docs`, `uv run zensical build --strict --clean`, `git diff --check`.
- `docs/sdd.md` and `docs/provenance/` are untouched; this plan carries no `## Result`.

## Review Focus

- **A branch carrying its parent's files.** Each cut ends with a `git diff --stat` against its parent and a commit count (Tasks 3–6).
- **A cherry-pick dropping a hunk silently.** Task 6's whole-stack `git range-diff` pairs all 17 source commits; every `!` must match a recorded anchor shift, and the four fix commits are the only unpaired rows.
- **A conflict deleting `main`'s text.** Task 2 diffs the rebase against `main` and counts the changelog line; the P4.5 section and P4.3 row survive.
- **A skills test proving only the flag.** Task 5 pins `--no-skills`, records the real-child check in `BACKLOG.md` with its reopen condition, and says so in the request.
- **A cut changing what a cycle does.** Only findings 2–5 are new behaviour; every other paired commit must match its source patch.
