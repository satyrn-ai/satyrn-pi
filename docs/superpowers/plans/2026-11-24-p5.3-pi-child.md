# P5.3 The Pi Child Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Written in the same session as the code.** The failing-first runs it cites are
> the ones that happened, recorded in order.

**Goal:** after a trial's workspace is prepared, `satyrn-pi eval` starts Pi in
print mode inside it, closes stdin, gives it a private agent directory and a shared
session directory, loads the resolved extensions in order, and records the
`session-ended` boundary with the trajectory beside it.

**Architecture:** One module, `src/satyrn_pi/session.py`, owns argv, environment,
the agent profile and the trajectory; it receives the spawn callable and the clock,
so nothing in the default suite starts a process. `cli.RealProbes` supplies the one
real spawn. The trial record is the only place the boundary is written.

**Tech Stack:** Python 3.12+ standard library (`subprocess` only behind the real
probe, `json`, `pathlib`, `secrets`), `pytest`, Pi 1.5.2.

**Spec:** `docs/superpowers/specs/2026-11-24-p5.0-eval-cli-design.md`
**Domain:** [`docs/domain.md`](../../domain.md) — the session boundary and the record tree.

## Global Constraints

- Branch `p5.3/pi-child`, stacked on `p5.2/workspace-preparation`; one pull request.
- No process, socket or model in the default suites. `subprocess` appears only in
  `cli.RealProbes`; `tests/python/**` never imports it, so the tripwire needs no
  exemption.
- The child's working directory is the prepared workspace; the prompt reaches it as
  an argument, never as a file inside the tree.
- `stdin` is `/dev/null`, `PI_CODING_AGENT_DIR` points inside the trial, and the
  session directory is shared across the job — the shape later redispatch needs.
- Extensions are passed with explicit `-e` in order, with discovery off, so the
  child's extension list is exactly the list the record carries.
- The agent profile is written from the resolved base URL and pinned model, so the
  child provably points at the server the job health-checked.
- Model requests are counted from the session artifact, not from terminal output.
  `run.json` says `"counts_source": "sessions"` from this cycle on.
- Deadline, process-group kill and `stopped` belong to P5.4. A child that exits
  non-zero is a session that ended badly, not a trial that was stopped.

## Review Focus

- **A spawn layer that never spawned.** Every default test injects a fake; the
  live run in the evidence below is the only proof the real call works. Pinned by
  the recorded transcript, not by a mock assert.
- **A private directory that reads someone's settings.** The child's agent
  directory is created inside the trial; a test asserts the profile names the
  job's base URL and model and nothing else is copied.
- **A boundary that is written too late.** `running` is written before the spawn
  and `session-ended` after it, so a kill between them leaves an honest record.
  Pinned by asserting the file after each step.
- **A count derived from output.** Requests are counted from `trajectory.jsonl`;
  a fake spawn that prints a number changes nothing.
- **A trial that looks finished.** `session-ended` is not final, carries no
  verdict and no score, and cannot be read as a result.

## Review (2026-11-26)

Reviewed by Kimi K3.1 against the spec, `docs/domain.md`, the plan and the test
rules. Six findings, all corrected with failing tests first. Pytest 129 → 138.

- **P1, fixed:** `count_requests` caught only `JSONDecodeError`, so a trajectory
  line holding `null`, `[]` or a scalar raised `AttributeError` *after* the child
  had exited — leaving a trial stuck at `running` with no `run.json`. Non-object
  entries are now skipped, with a parametrized test for all five scalar shapes.
- **P1, fixed:** the new worker-entry check still accepted `../outside.ts` and an
  absolute path, because `pathlib` discards the base for both. The entry is now
  resolved and must stay inside the worker directory; both shapes have tests.
- **P1, fixed:** a child that exited silently produced exit 2 with nothing on
  stderr, against the guide's promise. The CLI now always prints the trial and
  status, then the child's stderr tail when there is one.
- **P2, fixed:** `session_argv` took a `workspace` it never used; removed, and the
  test helper no longer supplies it.
- **P2, fixed:** the "not the output" test never supplied output, so it could not
  pin what it claimed. The fake child now prints `999` and the count stays 2.
- **P2, fixed:** the sharing test inspected one argv. Renamed, and a CLI test now
  asserts every child gets the same session directory and a different id.
- **Cleared:** the child boundary, stdin, the private profile, the prepared →
  running → session-ended order, the trajectory-derived count, the fake spawn and
  the fake clock.
