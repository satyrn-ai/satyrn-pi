# P5.1 Eval Resolution and Records Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `satyrn-pi eval` resolves the worker, Pi, suite and server, prints what it
resolved, refuses to start when any of them is wrong, and leaves `job.json` and
`run.json` behind — proven without starting a process or opening a socket.

**Architecture:** A small Python package under `src/satyrn_pi/`: a CLI that does
nothing but orchestrate, and four probes it receives as callables — worker lookup,
Pi version, suite load and server health. Tests pass fakes, so the default suite
stays process- and socket-free and the tripwire never needs an exemption.

**Tech Stack:** Python 3.12+, standard library only (`argparse`, `json`,
`datetime`, `pathlib`, `urllib` for the real probe), `pytest`.

**Spec:** `docs/superpowers/specs/2026-11-24-p5.0-eval-cli-design.md`
**Domain:** [`docs/domain.md`](../../domain.md) — the record tree and resolution order.

## Global Constraints

- Branch `p5.1/eval-resolution`, stacked on `p5.0/phase-5-cycles`; one pull request
  based on that branch.
- No subprocess and no socket in tests. `urllib` appears only inside the real
  health probe, which tests never call; `subprocess` does not appear at all.
- `pyproject.toml` gains `[project.scripts] satyrn-pi = "satyrn_pi.cli:main"`.
- Pi resolves from `node_modules/.bin/pi` first — pinned at exactly `1.5.2` in
  `devDependencies`, so `npm ci` supplies it — and from `PATH` only when the
  project install is absent. The global Pi is never modified or required.
- `runs/` stays ignored; nothing this cycle writes lands outside a tmp path in tests.
- The Pi gate accepts `^1.1.0` and flags anything that is not the **1.5.2** target
  as unverified, never as failed.
- No suite, grader, verdict or score is invented. Fixture trials carry the numbers.
- Vocabulary follows [the glossary](../../glossary.md): a suite holds **tasks**, a
  trial is one attempt at one of them, and a job aggregates trials. `--suite` and
  `run.json` are kept deliberately, as the [vocabulary review](../research/2026-11-16-vocabulary-review.md)
  requires, even though Harbor calls the collection a dataset.

## Review Focus

- **A probe that hides a process.** If the real probes are module-level constants,
  a test that forgets to inject one dials the network. Pinned by probes being
  function parameters with no defaults for the network one.
- **A gate that fails on a legal version.** 1.1.0 is inside the declared range, so
  it must run and be recorded as unverified; only an out-of-range version stops.
- **A resolution that silently prefers the machine.** The project's pinned binary
  wins over `PATH`, and the record says which one ran.
- **A total that is not a sum.** Model requests aggregates; elapsed seconds is one
  clock per job, and a test fails if the two are added together.
- **A half-made run.** An ambiguous worker, an out-of-range Pi or a dead server
  must each leave no job directory behind. Pinned by asserting the directory's
  absence, not just the exit code.
- **A suite that carries outcomes.** Request counts and clocks belong to trials
  recorded during a job, never to shipped suite data. Pinned by the suite fixture
  having no numeric results and by aggregation reading trial records.

### Task 1: Fixtures for a suite, trial records and a worker

**Files:**
- Create: `tests/python/fixtures/eval/suite-basic/suite.json`
- Create: `tests/python/fixtures/eval/trials/trial-01.json` (and `-02`, `-03`)
- Create: `tests/python/fixtures/eval/worker-stub/package.json`

**Interfaces:**
- Consumes: nothing.
- Produces: shapes P6.1 and P8 cite. A suite is a directory with `suite.json`
  carrying `name`, `version` and **`tasks`** — each task an `id`, `instructions`,
  `fixture` and `verification`. A trial record carries the **outcome** of one
  attempt: `task`, `model_requests`, `elapsed_seconds`. A worker is a directory
  whose `package.json` carries `name`, `version` and a `satyrn.worker` entry path.

- [ ] **Step 1: Write the suite fixture as data about work, not results**

Three tasks with ids, instructions, a fixture path and a verification note. No
counts and no clocks anywhere in it: those are outcomes, and the suite ships as
package data long before any attempt happens.

- [ ] **Step 2: Write the trial-record fixtures with numbers that cannot be confused**

Requests 2, 3 and 5, so the job total 10 differs from every individual record;
clocks 1.5, 2.25 and 4.0, whose sum 7.75 is not the job's own clock and must never
be published as one.

- [ ] **Step 3: Write the worker fixture**

`{"name": "@satyrn-pi/fixture-worker", "version": "0.0.1", "satyrn": {"worker": "./worker.ts"}}`.
No TypeScript file: P5.1 resolves a worker, it does not load one.

### Task 2: Resolution, with probes passed in

**Files:**
- Create: `src/satyrn_pi/resolve.py`
- Test: `tests/python/test_resolve.py`

**Interfaces:**
- Produces: `resolve_worker(explicit: Path | None, installed: Callable[[], Path | None]) -> Worker`,
  `resolve_pi(version: str, peer_range: str, target: str = "1.5.2") -> Pi`,
  `resolve_suite(name: str, root: Path) -> Suite`.
- `Worker` carries `path`, `version`, `source` (`"explicit"` or `"installed"`);
  `Pi` carries `version`, `verified: bool`; `Suite` carries `name`, `version`,
  `tasks` and no results.

- [ ] **Step 1: Write the failing tests**

Cases: an explicit path wins even when the installed lookup returns a different
worker; with no explicit path the installed one is used and `source` says so; when
neither resolves, a `ResolutionError` names both attempts; when both would resolve
**and differ**, the run stops rather than choosing; a worker directory without
`package.json` is not a worker; `elapsed`/`requests` totals are not computed here.

For Pi: a project install at `node_modules/.bin/pi` wins over a `PATH` binary and
is recorded as `project`; with no project install the `PATH` binary is used and
recorded as `path`; `1.5.2` is verified; `1.1.0` resolves with `verified is False`;
`1.0.0` and `1.7.0` raise `ResolutionError`; `^1.1.0` is parsed from
`package.json` rather than hard-coded.

- [ ] **Step 2: Run the tests and confirm they fail**

Run: `uv run pytest tests/python/test_resolve.py -q`
Expected: FAIL — `ModuleNotFoundError: satyrn_pi.resolve`.

- [ ] **Step 3: Implement the resolvers**

No default argument for the installed lookup: a caller that forgets it gets a
`TypeError`, not a network call. The peer range is read from `package.json` in the
repository root and compared with a small range parser that handles `^`, `~`, and
bare minimums — no new dependency.

### Task 3: Preflight, and a job directory only after it passes

**Files:**
- Create: `src/satyrn_pi/records.py`
- Test: `tests/python/test_records.py`

**Interfaces:**
- Produces: `job_id(now: datetime) -> str` returning `<YYYY-MM-DDTHHMMSSZ>-<six hex>`;
  `job_path(runs: Path, suite: Suite, job: str) -> Path` returning
  `runs/<date>-<suite>/<job>`; `write_job(path, job) -> None`;
  `write_run(path, run) -> None`.

- [ ] **Step 1: Write the failing tests**

Aggregation reads the trial-record fixtures, never the suite. `job_id` is UTC,
fixed-width and matches `^\d{4}-\d{2}-\d{2}T\d{6}Z-[0-9a-f]{6}$`;
two ids built from the same instant differ; `job_path` nests under
`runs/2026-11-24-basic/<job>/`; `write_job` writes valid JSON with the suite
version, CLI version, worker path and version, Pi version and base URL; `write_run`
writes `model_requests` as the sum of trial requests and `elapsed_seconds` as a
number that is **not** that sum, and a test fails if the two are equal to the trial
sum — the anti-sum guard.

- [ ] **Step 2: Run them and confirm they fail**, then implement.

### Task 4: The CLI

**Files:**
- Create: `src/satyrn_pi/cli.py`
- Modify: `pyproject.toml` — add `[project.scripts]`
- Test: `tests/python/test_cli.py`

**Interfaces:**
- Consumes: the resolvers and record writers.
- Produces: `main(argv, *, probes) -> int`. Probes are a dataclass of callables:
  `installed_worker`, `pi_version`, `server_health`. Tests construct it with fakes.

- [ ] **Step 1: Write the failing tests**

- `main(["eval", "--suite", "basic"], probes=...)` over a suite of three tasks writes
  `job.json` and `run.json` under a tmp `runs/`, returns 0, and prints one line per
  resolved input.
- The printed resolution matches `job.json` field for field.
- An ambiguous worker returns 2, prints the reason, and **no** `runs/` directory
  exists afterwards.
- An out-of-range Pi returns 2 with the same absence.
- A failing health probe returns 2 with the same absence, and never writes a job.
- `--worker` pointing at the fixture worker is recorded as `explicit`.
- `--base-url http://127.0.0.1:9999/v1` is carried into `job.json` unchanged.
- `eval --help` exits 0 without touching any probe — the probes dataclass records
  calls, and none happened.

- [ ] **Step 2: Run and confirm they fail**, then implement `main` so resolution
  prints, preflight gates, and records are written in that order.

- [ ] **Step 3: Prove the tripwire still bites**

Plant `import subprocess` in `src/satyrn_pi/cli.py`, run `npm test`, and confirm the
default-test guard fails; revert.
