# P5.4 The Deadline and the Stopped Trial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a session that outlives its deadline is killed as a process group and
recorded as `stopped` — a status distinct from a failure — and one real trial runs
end to end under a deadline that did not fire.

**Architecture:** P5.3's `run_session` gains a deadline and a stop path; the real
process adapter translates the child's timeout and kills the group it created. The
trial record gains its final `stopped` shape, and the job stops asking for work
once a bound has fired.

**Tech Stack:** Python 3.12+ standard library (`subprocess`, `os`, `signal` behind
the real adapter and nowhere else), `pytest`, Pi 1.5.2.

**Spec:** `docs/superpowers/specs/2026-11-24-p5.0-eval-cli-design.md`
**Domain:** [`docs/domain.md`](../../domain.md) — "the deadline is the other end".

## Global Constraints

- Branch `p5.4/deadline`, stacked on `p5.3/pi-child`; one pull request.
- No process, socket or model in the default suites; `subprocess` stays inside
  `cli.RealProbes`' adapter, so the tripwire needs no exemption.
- The deadline bounds **one session**, and a fired deadline stops the job: after a
  bound has been reached, starting more children is not bounded.
- `stopped` is final and never carries a verdict or a score; `graded` is the only
  status that may.
- A stopped trial records what happened — deadline marker, exit status, clock,
  requests so far, trajectory if there is one — rather than an empty record.
- Exit code 2 for a stopped job, and `run.json` written last, exactly as a failed
  child is handled today.

## Review Focus

- **A verdict on a stopped trial.** `write_trial` refused result fields on
  non-final statuses only, so `stopped` — which is final — could carry one. Pinned
  by a test: only `graded` may carry `verdict` or `score`.
- **A kill that leaves grandchildren.** The child is started in its own session, so
  the kill is `killpg`, not `kill`. Proven live by checking no child survives.
- **A timeout swallowed as success.** The stop path must record `stopped`, exit 2
  and a marker; a test fails if a fired deadline can look like a clean session.
- **A job that keeps going after the bound.** Pinned by a fake that would answer
  three trials and a test asserting one record and no third child.
- **A clock restarted for a stop.** The stopped span is measured from the same
  start as a clean one; a stop must not look quicker than it was.

## Review (2026-11-26)

Reviewed by Kimi K3.1 against the spec, `docs/domain.md`, the plan and the test
rules. Five findings, corrected with failing tests first. Pytest 150 → 158 after
the rebase onto P5.3's own review fixes.

- **P1, fixed:** `kill_group` looked the group up with `getpgid(pid)`. A child
  reaped in the instant between EOF and the timeout raises `ProcessLookupError`,
  and the handler skipped the kill while descendants survived. The child leads its
  own session, so its pid *is* the group id: `kill_group` now signals that pid
  directly, and two tests pin the call and the already-empty group.
- **P1, fixed:** the summary called a stopped session an ended one —
  `sessions 1 ended, … 1 stopped` for a single stopped trial. Ended is now
  `records - stopped`, with the terminal line asserted.
- **P2, fixed:** `argparse` accepts `nan` and `inf`, and `nan <= 0` is false, so a
  non-finite deadline reached the timeout arithmetic and could be written as a
  non-standard JSON number. The preflight now requires a finite positive value;
  the test is parametrized over `0`, `-1`, `nan`, `inf` and `-inf`.
- **P2, fixed:** two tests did not pin what their names claimed. The stopped
  session now asserts the reap call (`communicate(None)` after the kill), and the
  deadline is read from `job.json` *inside* the first spawn rather than after the
  run.
- **P2, fixed differently from the recommendation:** `FINAL` had become
  test-only, and the reviewer suggested deleting it. But the guide, the domain and
  P5.2's plan all promise that `graded` and `stopped` are final, and nothing
  enforced it. Rather than delete the claim, `write_trial` now refuses to reopen a
  final record — a final trial may be rewritten at the same status, never turned
  back into `running`. The constant has a production consumer and the claim is
  true; two behavioural tests replace the self-referential one.
- **Cleared:** the timeout ordering, the stopped/failed distinction, the no-verdict
  guard, the stop-before-further-trials rule, `run.json` last, and the fake-only,
  clock-explicit tests.

  `stopped: 1`, `exit_status: 2`. `pgrep` for a Pi child afterwards found none,
  so the process-group kill reached everything the child started. Re-run after the
  review's pid change, with the same result.

  `session.TimedOut` needs the real `subprocess` exception, and a test raising it
  would import `subprocess` and trip the default-test guard. The deadline run
  above is its proof; the stop path it feeds is covered by a fake handle.
- **Request counts vary between runs** (10 earlier, 5 now) because the model chose
  different numbers of tool calls. That is a reason to read the count, never to
  treat either number as a rate.
