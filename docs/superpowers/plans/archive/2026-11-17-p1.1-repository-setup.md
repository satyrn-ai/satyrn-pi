# Plan: P1.1 repository setup

Infrastructure cycle. Populates `satyrn-ai/satyrn-pi` from the staging tree and
establishes both package skeletons, default test commands, the ignored `runs/`
and the repository-weight check. No product behaviour changes, so no spec; the
[P1.1 roadmap row](../../../ROADMAP.md#phase-1--repository-and-dependencies) and
the kickoff carry the agreed scope.

Builder calls, marked as mine rather than agreed: npm `scripts.test` is
`node --test tests/*.test.mjs`; Python tests live in `tests/python/` and run
through `uv run pytest`; the Python package uses the `src/` layout with the
`uv_build` backend; `requires-python = ">=3.12"` (raised from 3.11 because
`zensical-glossary` requires it); the weight check walks the
filesystem skipping ignored directories instead of spawning `git`.

## Budgets the weight check enforces

Seed tree is 14 documentation files plus package skeletons, well under 200
files and 1 MiB of text. Caps: 200 files, 1,000,000 bytes, counted over the
walked tree (`.git`, `node_modules`, `.venv`, `runs/` and cache/build outputs
excluded). The source failure mode was 2,245 tracked files under `runs/`
([source inspection](../research/2026-11-16-source-inspection.md)); these caps
trip long before that shape can recur. Recalibration needs a recorded reason.

## Verification

- `diff -r` of the copied tree against `git archive 44bdbd61 satyrn-pi`
  (excluding `README.md`) is empty.
- The weight test fails while its module does not exist, then passes; the
  fixture tests show both the over-budget failure and the under-budget pass.
- `uv run pytest` fails on the missing package, then passes after it exists.
- `npm test` and `uv run pytest` use no model, no network and no subprocess.
- `git check-ignore runs` succeeds.
- Registry checks recomputed: `npm view satyrn-pi` and
  `curl -s -o /dev/null -w "%{http_code}" https://pypi.org/pypi/satyrn-pi/json`.
