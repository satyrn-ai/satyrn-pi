# P6.0 Suites and grading: phase 6 design

## Reviewer brief

**Intent:** a finished workspace earns a grade whose identity, rules and evidence
someone who did not run it can check, so a later score or gate is trusted rather than
assumed. (Paul, 2026-11-26.)

**Decisions:** four cycles — P6.1 suite data, P6.2 grading, P6.3 witness qualification,
P6.4 feedback and the guide. The suites are copied byte-verbatim from `0e4a9b68` into
`src/satyrn_pi/suites/`, and the repository-weight budget rises to 320 files and 2.5 MB
with that reason recorded. Grading runs through an injected runner: default tests pass a
stub, the real adapter spawns pytest beside the existing child spawn. A grade is
`suite/version` plus a content hash over expected IDs, grader hashes and runner argv;
two grades agree only when both do. Easy's inherited four-check grade stays primary,
with a corrected or stricter grade beside it under its own identity. Feedback is
`expected`/`observed` under its own rule version, re-earned from `3e20e161`, and gate-
message versions are never merged. The guide is `docs/scoring-and-evidence.md`,
unpublished like the eval CLI guide.

**Non-goals:** a model, network or graded run; a settle or redispatch remedy; the
Education challenge UI; relabelling a historical grade; claiming the eval CLI is on
`main`.

**Verification:** a planted hash mismatch, a duplicated expected ID and a missing grader
module each fail; a collection error and zero collected checks are not passes; a
corrected grade coexists with the primary; `npm test`, `uv run pytest`, `npm run
check:docs` and the strict build pass with no default test spawning a process.

## Intent and why

P5.1–P5.4 record what was resolved, prepared, run and stopped; nothing says what a
finished workspace earned. Phase 6 defines the grade, proves it agrees with the
preserved expectations, and publishes the rules every later phase cites.

## What the inherited grade is

Each suite at `0e4a9b68` carries `expected.json` — pytest node IDs, Easy 4, Medium 18,
Hard 34, all prefixed `grader_tests/` although the source directory is `grader/`; the
copy is renamed on install, so the prefix is preserved expectation. `layout.json` sits
beside it, and the graders are ordinary pytest modules importing the workspace's own
`app`.

Grading copies those tests to `<workspace>/grader_tests`, runs
`uv run --with pytest pytest -q -rA grader_tests` with `PYTHONPATH=<workspace>` (`uvx`
without a `pyproject.toml`), and reads `PASSED <id>` lines: a pass is exit 0 with
nothing missing, and `checks_ran` is recorded so a collection error never reads as
"everything failed" ([compatibility](../research/2026-11-16-grading-compatibility.md)).

## P6.1 — Suite data

Copy byte for byte from `learn/code/suites/<name>/` into `src/satyrn_pi/suites/<name>/`
— `base/`, `fixtures/known-good/`, `fixtures/known-broken/`, `grader/`, `expected.json`,
`layout.json`, `prompts/`, the three `uv.lock` files and Hard's `data.db`, unedited.
`SOURCES.json` gives each file's source path, commit and SHA-256, and a test recomputes
every hash, so "verbatim" is checked rather than asserted.

The loader refuses, naming the identifier, a duplicated expected ID, an ID whose module
is absent from `grader/`, an ID outside the `grader_tests/` prefix, or an entry set that
differs from the file set; `job.json` gains the resolved version.

The weight budget moves here because the copy cannot land without it: 127 files and
912,852 bytes against 200 and 1 MB, plus 119 files and 904,035 bytes. It becomes 320
files and 2.5 MB — run output, traces and workspaces stay out; pinned inputs never were
in.

A task's `instructions` come from its `prompts/01.md`; later prompts are copied but
unreferenced — a multi-prompt task is not this phase's work.

## P6.2 — Grading

`grade(workspace, suite, *, runner)` takes the runner as an argument, shaped
`runner(argv, cwd, env) -> (returncode, output)` like `session.spawn`: default tests
supply a stub returning recorded output, and `RealProbes` supplies the adapter that
spawns, beside `RealProcess`. No default test imports `subprocess`, so the tripwire
stays green and the stub is the extension seam (BRIEF rule 6).

Grading runs after the session, outside the workspace: `grader/` is copied to
`<workspace>/grader_tests`, the runner is called there, and the copy is removed.
`missing` is every expected ID without a `PASSED` line, and `checksRan` is false on a
collection error, so a grader that never ran cannot become a pass.

```text
verdict.json
  suite, grade       suite name and version; grade id, primary flag, content hash
  checks, missing    [{id, passed}] for every expected ID, and those that failed
  checksRan, passed  false on a failed collection; true only on exit 0, all run, none missing
  grader, runner     copied-from path and per-file SHA-256; argv and cwd
```

`trial.json` reaches `graded` only with a verdict written; `run.json` carries each
trial's grade id and the count that passed. A session that ended ungraded stays at
`session-ended`, which `trial.py` refuses a verdict at.

## Grade identity, and the primary grade

A grade's ID is `<suite>/<grade_version>`, e.g. `easy/inherited/1`; its content hash
covers the expected ID list, every grader file's SHA-256, the runner argv and the
feedback rule version. Two verdicts share a grade only when ID and hash both match, and
the same ID with a different hash is a new version. Easy's inherited four-check grade is
`primary: true`; a stricter Easy or corrected Medium grade is a different ID written
beside it, never in place of it, and no written record is relabelled.

## P6.3 — Witness qualification

A witness is a workspace tree plus an expected per-check outcome. `witnesses.json` per
suite names the copied `known-good` and `known-broken` trees and lists, per check,
whether the inherited grade accepts or rejects each — the leniency
[compatibility](../research/2026-11-16-grading-compatibility.md) records, written down
and kept, because correcting it is a distinct grade version, not a quiet fix. Qualifying
a grader runs pytest, so that path is a marked integration test CI does not run, with a
default test asserting the mark and the skip. The record is a research note — command,
pytest tail per witness, check counts, hashes — and no grade version is qualified before
it exists.

## P6.4 — Feedback and the guide

Feedback is its own contract because a changed message can change the model's next
action while every expectation stands. A verdict carries
`feedback: {rule_version, expected, observed}`: what the acceptance test wanted and what
it found, in the re-earned `3e20e161` words. `rule_version` moves when a message
changes; the grade ID does not, and the two source revisions are recorded separately
rather than merged. `docs/scoring-and-evidence.md` is the contributor's guide: failed
versus unrun checks, what a grader can and cannot see, how expected and observed
feedback differ from the oracle verdict, and how strong the evidence is. It follows
`docs/eval-cli.md` — repository-only, excluded from the site, linked from
`docs/domain.md` — with glossary entries for grade, verdict and witness.

## Left to the builder

- Module layout — whether suites, grading and feedback are one module or three — and
  the `verdict.json` field names, within the facts listed, plus whether `SOURCES.json`
  ships in the wheel.
- How the stub represents a collection error and zero collected tests.

## Verification

- Every `SOURCES.json` hash recomputes, and a planted one-byte edit fails; a duplicated
  expected ID, an unlisted grader module and a stray file each fail the loader, each
  shown failing first; a stub reporting every expected ID passes while none, a subset,
  and a collection error all fail, the last two naming the missing IDs.
- A verdict carries the grade ID, content hash and primary flag; a corrected grade in it
  leaves the primary untouched, and a changed `rule_version` leaves its hash unchanged
  while a changed grader file moves it.
- The marked integration test is skipped by default, no default test starts a process,
  the tripwire proves it, and both suites, `npm run check:docs` and
  `uv run zensical build --strict` pass.
