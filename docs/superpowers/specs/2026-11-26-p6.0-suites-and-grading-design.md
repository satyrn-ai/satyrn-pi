# P6.0 Suites and grading: phase 6 design

## Reviewer brief

**Intent:** a finished workspace earns a grade whose identity, rules and evidence
someone who did not run it can check, so a later score or gate is trusted rather
than assumed. (Paul, 2026-11-26.)

**Decisions:** six cycles — P6.1 data and provenance, P6.2 bounded grading for Easy,
P6.3 Medium's grader, P6.4 Hard's grader, P6.5 cross-suite qualification, P6.6
feedback and the guide. Fixtures, prompts, expectations and layout are copied from
`0e4a9b68`; the 24 graders stay remote references and are re-earned in their own
cycles. `suite.json` is port-authored, one task per suite, its instruction the joined
prompts under `promptMode: joined`. Grading runs through an injected runner from a
copy outside the workspace, with the workspace's pytest configuration,
`PYTEST_ADDOPTS`, `PYTEST_PLUGINS` and plugin autoloading suppressed and the
environment recorded. A grade is `suite/version` plus a hash over expected IDs,
grader hashes, runner argv and environment; feedback is versioned apart and never
enters it. A timed-out grader exits 2 and leaves its trial ungraded; a grader error or a failed primary
grade exits 1. The weight budget rises to 320 files and 2.5 MB, and I.3 moves both P5
references to "grading starts in P6.2".

**Non-goals:** a model, network or graded run; a settle or redispatch remedy; the
Education challenge UI; relabelling a historical grade; claiming the eval CLI is on
`main`.

**Verification:** a planted hash mismatch, a duplicated expected ID and a missing
grader module each fail; a collection error and zero collected checks are not passes;
a hung grader stops the run with no verdict; a corrected grade coexists with the
primary; both suites, the document checks and the strict build pass with no default
test spawning a process.

## Intent and why

P5.1–P5.4 record what was resolved, prepared, run and stopped; nothing says what a
finished workspace earned. Phase 6 defines the grade, proves it agrees with the
preserved expectations, and publishes the rules every later phase cites.

## What the inherited grade is

Each suite at `0e4a9b68` carries `expected.json`: pytest node IDs, Easy 4, Medium 18,
Hard 34, all prefixed `grader_tests/`. The IDs name modules and test functions, so a
rewritten grader keeps those names — that is what makes the list verbatim and the
rewrite checkable. The graders import the workspace's own `app`, and the source runs them from
`<workspace>/grader_tests` with `-q -rA`, reading `PASSED <id>` lines and recording
`checks_ran` ([compatibility](../research/2026-11-16-grading-compatibility.md)).

## P6.1 — Suite data and provenance

Copy the 95 non-grader files byte for byte into `src/satyrn_pi/suites/suite-<name>/source/`,
where `RealProbes.suite_root` and `resolve_suite` already look; `grader/` and its `canary`
stay out, because graders are re-earned. `SOURCES.json` records `copied`, `reference` for
the 24 remote grader files, and `authored`, and the loader's file-set check counts only
`copied` and `authored`, so a reference entry never reads as a missing file
([note](../research/2026-11-26-grading-environment.md#provenance-categories)).

Each suite gains an authored `suite.json`: one task, `fixture: "source"`, the joined prompts
as `instructions`, `promptMode: joined`. Every suite's first prompt asks only for the home
page, so grading Medium's 18 checks or Hard's 34 after prompt one would grade unasked work;
the source's own `single_prompt` mode joins them.

The loader also refuses a duplicated expected ID, an ID whose module is absent from the
suite's `graders/`, an ID outside the `grader_tests/` prefix, and a stray file.

## P6.2 — Bounded grading, Easy's four checks

`grade(workspace, suite, *, graders, runner, timeout)` takes the runner as an argument,
shaped `runner(argv, cwd, env, timeout) -> (returncode, output, outcome)`: default tests
supply a stub, `RealProbes` the adapter beside `RealProcess` that spawns. No default test
imports `subprocess`, so the tripwire stays green and the stub is the seam (BRIEF rule 6).
Easy's four graders are rewritten here, keeping their module and test names, and proven
against the suite's known-good and known-broken trees.

Grading runs after the session, outside the workspace: `graders/` is copied to a temporary
directory that becomes the working directory, the workspace is on `PYTHONPATH`, and the
workspace's pytest configuration, `PYTEST_ADDOPTS`, `PYTEST_PLUGINS` and plugin autoloading
cannot reach the run. Interpreter, argv, working directory and environment are recorded and
hashed ([isolation](../research/2026-11-26-grading-environment.md#pytest-isolation)).

`verdict.json` records the suite, the grade id and hash, every check with the missing IDs, the
outcome, the environment and the grader hashes. `outcome` is the whole contract: only `graded`
sets `passed` and moves `trial.json` to `graded`; a time-out kills the process group, writes
the record, leaves the trial `session-ended`, ends the run `stopped` with exit 2 and starts no
further trial; a grader error exits 1; a `stopped` trial is never graded. Exit is 0 only when
every trial graded and passed
([fields, outcomes and exit](../research/2026-11-26-grading-environment.md#bound-and-outcomes)).

## Grade identity, and the primary grade

A grade's ID is `<suite>/<grade_version>`, e.g. `easy/inherited/1`; its content hash covers
the expected ID list, every grader file's SHA-256, the runner argv and the recorded
environment. Two verdicts share a grade only when ID and hash both match. Easy's inherited
four-check grade is `primary: true`; a stricter or corrected grade is a different ID written
beside it, and no written record is relabelled.

## P6.3 and P6.4 — Medium's and Hard's graders

Each cycle rewrites one suite's graders to its preserved `expected.json` — 18 checks, then 34
— keeping the source's module and test names and the assertion each names, and proves them
against that suite's own known-good and known-broken trees. Medium and Hard carry different
contracts, so they are separate cycles; a check whose rewritten behaviour differs from its
witness becomes a P6.5 gap, never adjusted to agree.

## P6.5 — Cross-suite qualification

`witnesses.json` per suite names every witness and records, per check, whether the inherited
grade accepts or rejects it, so the leniency
[compatibility](../research/2026-11-16-grading-compatibility.md) records is written down and
kept rather than silently fixed. Execution-environment witnesses extend the per-cycle checks:
a hostile `conftest.py` and `pyproject.toml` in the workspace, an inherited `PYTEST_ADDOPTS`,
and a hanging app that must end `timed-out` with its group gone.

Running pytest is a marked integration test CI does not run, and a default test asserts the
mark and the skip. The record is a research note — command, pytest tail per witness, check
counts, hashes — and no grade version is qualified before it exists.

## P6.6 — Feedback and the guide

Feedback is a contract separate from the grade, because a changed message can change the
model's next action while every expectation stands. A verdict carries
`feedback: {rule_version, rule_hash, expected, observed}` — what the acceptance test wanted
and what it found, in the re-earned `3e20e161` words. `rule_version` moves when a message
changes and the grade ID does not; the two source revisions are recorded separately, never
merged.

`docs/scoring-and-evidence.md` is the contributor's guide: failed versus unrun checks, what a
grader can and cannot see, how expected and observed feedback differ from the oracle verdict,
how strong the evidence is, and that a joined trial is not comparable with the source's
per-prompt sessions. It follows `docs/eval-cli.md`: repository-only, excluded from the site,
linked from `docs/domain.md`, with glossary entries for grade, verdict, witness.

## The handoff from phase 5

The P5.4 row and the P5.0 spec both say "Grading, which P6.1 owns". I.3 changes both to
"grading starts in P6.2" while re-cutting the stack; after this branch rebases onto the
retargeted `p5.4` tip, its owner checks that wording before the rows land.

## Verification

- Every `copied` hash recomputes and a planted one-byte edit fails; a `reference` entry with
  no local file loads cleanly and a `copied` entry with no file fails; a duplicated expected
  ID, an absent grader module and a stray file each fail the loader, each shown failing first.
- A stub reporting every expected ID passes; none, a subset, and a collection error all fail,
  the last two naming the missing IDs; a time-out writes no `passed` and leaves the trial
  `session-ended`.
- A workspace `conftest.py`, `pyproject.toml` or inherited `PYTEST_ADDOPTS` cannot change a
  verdict, proven with a hostile witness; a failed primary grade exits 1 with the trial
  `graded`; a stopped or timed-out run exits 2 and starts no further trial.
- The marked integration test is skipped by default, no default test starts a process, the
  tripwire proves it, and both suites, `npm run check:docs` and the strict build pass.
