# P4.0 Getting Started setup: phase 4 design

## Reviewer brief

**Intent:** phase 4 teaches a stranger who arrived from a social post how to run
the subject model on their own machine, and leaves behind a reference host card
that can be checked rather than believed.

**Decisions:** setup is published as `docs/getting-started.md`, the site's third
page, promising a running model rather than a worker; b12066 comes from the
official `llama-b12066-bin-macos-arm64.tar.gz` and sits beside Homebrew's 12110
without replacing it, pinned by the asset's sha256 and the tag's source commit
rather than by tag alone; the weights are pinned to
`JetBrains/Mellum2.1-12B-A2.5B-Thinking-GGUF` at `4159d684`, Q4_K_M, 8,071,295,264
bytes, sha256 `ecc4d5b8…fa2755`; Darwin arm64 is the reference platform and every
other platform is published as unverified; one spec governs three stacked cycles
— P4.1 pin the reference, P4.2 reproduce it, P4.3 publish the page — and each
cycle ships its own plan, not its own spec.

**Non-goals:** the worker, the eval command and the suites; an eval-managed
server lifecycle; a second quant or build; Linux, CUDA and Windows instructions;
publishing either package; any rate claimed from a smoke run.

**Verification:** P4.1's card matches the publisher's own metadata for the build
and the weights; P4.2's answer comes from a server whose binary and weights match
that card; P4.3 publishes a third page while the published-set test still fails
on an unplanned fourth, and its digests match the card.

## Intent and why

Phase 4's row asked one cycle to record the configuration, choose a platform,
demonstrate a response and publish a page — three deliverables, three reviewers,
three pull requests. The row predates this machine's inspection, so the first job
is to make the configuration it names *exist here*.

## Who arrives at the page

A social post, the site's home page, a Getting Started button. They intend to
follow the instructions in order and copy-paste them, they are not reading for
understanding, and they will not debug: a step that fails in an unanticipated way
ends the visit. That is the installer BRIEF already describes — the person who
never clones the repository and never opens the roadmap. So the page carries
numbered steps, one action each, and a check after every step that would
otherwise fail silently. Nothing on the site points at setup today; the button
and the nav section are this phase's to add.

What it promises is *run the subject model on your machine*: the last step is a
request that returns an answer, and the last section says the worker which hands
that model a bounded task is not published yet and links the roadmap. Promising a
conversation with a worker would describe components from phases 5–9, which the
repository forbids.

## One page, published

`docs/getting-started.md`, a *Getting Started* nav section, three published
pages, and the published-set test edited in the same cycle — the test exists
because exclusion fails open, so it fails on an accidental page, and a cycle that
intends a third page changes it deliberately. Phase 9 appends its walkthrough to
this page rather than adding a fourth.

The page uses placeholders for paths and says so in one line; the card carries
the exact command with this machine's absolute paths. It also names the two
failures a first-time install hits here and nowhere else: macOS quarantines the
downloaded tarball, so the binary is killed on first run, and a `llama-server`
already on `PATH` is likely Homebrew's 12110.

## The reference host card

P4.1 produces the project's first host card — the shape later records copy when a
rented batch qualifies a host. It lives under `docs/superpowers/research/`, which
is excluded from the site, so the record is repository-only and P4.1 makes no
site change.

- **Build:** llama.cpp **b12066** — source commit
  `713319e28492d319b81e49646151f6bbdb9d4551` and the official
  `llama-b12066-bin-macos-arm64.tar.gz` asset, 16,548,566 bytes, sha256
  `909053143be864f6b2c45b45e140575904fde163978d33cea53f30f318e09a19`, extracted
  into its own directory. Homebrew's 12110 stays installed and out of the
  documented command. A tag alone is not a binary pin, which is what the
  [rig note](../research/2026-11-16-reference-rig.md) asks for.
- **Weights:** `JetBrains/Mellum2.1-12B-A2.5B-Thinking-GGUF` at revision
  `4159d684ffdb09ba89dc2a58feb3e75c54eef036`, file
  `Mellum2.1-12B-A2.5B-Thinking-Q4_K_M.gguf`, 8,071,295,264 bytes, sha256
  `ecc4d5b8107fc219e23c494b2d107552137637b6c6002ee713e0ba8af7fa2755`.
- **Settings, preserved rather than measured:** context 50000, max tokens 16384,
  temperature 1.0, top p 0.95, top k 20, API base `http://127.0.0.1:8001/v1`.
- **Platform:** Darwin arm64 on the reference machine — M5 Max, 128 GB,
  macOS 27.2.1. Linux, CUDA and Windows are published as unverified, because flag
  names and artifacts differ between platforms even at one server version.
- **Serve command:** the whole line, with flags taken from b12066's own `--help`.
  The macOS artifact builds with Metal, so the offload is a recorded choice
  rather than a default someone has to infer.
- **Memory:** the page publishes the allocation llama.cpp reports at startup for
  the documented command — model, KV cache and compute — which a reader
  recomputes from that same command; the card records the observed peak footprint.

## The stack

Three cycles, one pull request each, based on the branch before it and retargeted
to `main` as its parent merges — so Nicola reads the pin before the download.

| Cycle | Ships | Leaves |
| --- | --- | --- |
| **P4.1** | The host card: build tag, source commit, asset size and sha256, weights revision, file size and sha256, the preserved settings, the serve command, each with the metadata it came from. | Fetching anything; a running server; site changes. |
| **P4.2** | b12066 installed, weights fetched and verified against the card, a served model, a demonstrated answer, the recorded walk through the page's steps, the reported allocation and observed footprint. | Publishing; prose. |
| **P4.3** | The page, the nav section, the third published page, the updated published-set test, and a check that the page's digests still match the card. | Phase 9's walkthrough sections; any instruction for an unverified platform. |

## Decisions

- **Publish setup now, promising a running model.** The alternative leaves phase
  9 nothing to finish. (Paul, brainstorm.)
- **The arrival is our home page and our button**, read from BRIEF's installer.
  (Paul, confirmed.)
- **One spec, three cycles:** the shared calls are made once here. (Assistant.)
- **Walk the steps in P4.2, from nothing.** Steps written before they are run,
  then executed in order from a directory with neither build nor weights and a
  `PATH` without Homebrew's server, with the walk recorded in the card. A machine
  no one here has touched stays phase 9's, with Ben. (Paul, on recommendation.)
- **The card lives inside `docs/superpowers/`**, where a new file cannot become a
  fourth published page. (Assistant.)
- **b12066 from the official macOS artifact, beside Homebrew's build.** The
  artifact exists, so the rig's fallback decision is unnecessary. (Assistant.)
- **The plain quant, not `mtp/`:** same repository, different digest, and naming
  the directory stops a later reader pinning the wrong hash. (Assistant.)
- **Darwin arm64 is the reference platform, not Linux/CUDA.** The artifact and
  the machine are here, and an unexercised platform is published as unverified.
  (Paul, confirmed.)
- **Digests appear on the page and in the card**, checked in P4.3. (Assistant.)
- **No server-management code.** Provisioning stays outside eval, and a helper
  that starts servers is the lifecycle phase 5 excludes. (Assistant.)

## Verification

- Every value in P4.1's card carries its source, quoted rather than transcribed.
- P4.2's server reports build b12066 and the pinned digests before it answers,
  and the answer and the figures come from that session.
- P4.3's `zensical build --strict` is green with three pages; the published-set
  test fails on a planted fourth and passes on the tree; both suites pass.
- Every step on the page appears in the card's walk, in that order, and a step
  the walk never ran does not reach the page.
