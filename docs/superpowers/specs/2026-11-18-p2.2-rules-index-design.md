# P2.2 rules index and mapped records: design

## Reviewer brief

**Intent:** a new contributor's agent finds the effective rules from a root
`AGENTS.md` that indexes them, and the repository has honest records for
deferred work and observed failures.

**Decisions:** `AGENTS.md` is a short index with document budgets, not a copy of
the process; budgets live there because `docs/sdd.md` is preserved and
immutable; only existing destinations are linked; `BACKLOG.md` and
`docs/pathologies.md` may be empty; the wrapper skill points, it does not
duplicate; provenance is verified by a recorded run of the documented diff.

**Non-goals:** the cap checker (P2.3), vocabulary checks (P2.4), tripwire and
import check (P2.5), the discovery demonstration and phase close (P2.6), any
runtime code, edits to preserved files.

**Verification:** every link in `AGENTS.md` resolves now; both preserved files
match source `0e4a9b68`; Pi discovers the wrapper skill; default suites stay
green and subprocess-free.

## Intent and why

P2.1 gives contributors a setup path but no root instructions: an agent opening
this repository finds `BRIEF.md`, a transition record, preserved source rules
and a roadmap, but no file that says which to read first or which numbers
govern a new cycle. The source project had an `AGENTS.md`; the port has only
its verbatim copy under `docs/provenance/`.

P2.2 installs the effective rules as an index, adds the two records the close
checklist expects, and writes modest document budgets so reviewers receive a
short brief instead of a corpus.

## Goals

- Root `AGENTS.md`, at most 80 lines: reading order and precedence, the
  cycle, document budgets, default checks, hard boundaries, and links to every
  destination that exists after this cycle.
- `.agents/skills/satyrn-pi/SKILL.md`: a thin skill that routes a contributor's
  agent to `AGENTS.md` and `docs/sdd.md` without repeating them.
- `BACKLOG.md`: header, entry format, reopen-condition rule, zero entries.
- `docs/pathologies.md`: honesty header, entry format with required evidence,
  zero entries.
- Byte-verification of `docs/sdd.md` and
  `docs/provenance/mellum-worker-AGENTS.md` against source `0e4a9b68`, run
  against a local source checkout and recorded as PR evidence.
- `ROADMAP.md` updates: P2.2's status and links, and wording that it links only
  existing destinations (P2.6 keeps the all-links-resolve check).

## Non-goals

- The executable cap/lifecycle/evidence checks (P2.3); this cycle states the
  budgets, it does not enforce them.
- The vocabulary budget and retired-term check (P2.4).
- The default-test tripwire and one-way import check (P2.5).
- The new-contributor discovery demonstration and phase close (P2.6).
- Editing `docs/sdd.md` or `docs/provenance/`; rewriting P2.1 documents. Stale
  references in them are corrected, not their content.
- Retrofitting a reviewer brief onto the P2.1 spec.

## Anti-goals

- A second copy of the process rules in `AGENTS.md`; it is an index.
- A backlog or pathology entry invented to fill a template.
- A wrapper skill that duplicates or overrides Superpowers.
- Broken links to destinations that land in later cycles.
- A new subprocess, model or network dependency in the default suites.

## Constraints

- Branch `p2.2/rules-index`, stacked on `p2.1/contributor-setup`; one PR into
  that branch for Nicola.
- `docs/sdd.md` and `docs/provenance/mellum-worker-AGENTS.md` stay byte-for-byte;
  the verification command comes from `docs/provenance/README.md`.
- The source checkout used for verification is
  `~/projects/pauleveritt/mellum-worker`; the command is recorded so anyone can
  repeat it.
- Plain Markdown; document caps in `docs/sdd.md` still apply, and the new
  budgets tighten them for new work.

## Decisions

- **Budgets live in `AGENTS.md`.** `docs/sdd.md` is preserved and cannot carry a
  port-specific change. `AGENTS.md` states that 150-line specs, 250-line plans
  and a 30-line reviewer brief tighten the preserved 400-line caps for new work;
  the original stays quoted and dated in `docs/sdd.md`. (Assistant's call,
  grounded in the preservation rule.)
- **Links only what exists.** P2.2 links the cap test and pathology entries after
  those exist; P2.6's phase close resolves every active path. (Paul's decision.)
- **Empty records are valid.** `BACKLOG.md` and `docs/pathologies.md` ship with
  formats and no entries; the acceptance rules forbid inventing deferred work or
  observed failures. (Assistant's call, following the acceptance text.)
- **The wrapper points.** `.agents/skills/satyrn-pi/` carries a short routing
  description and links; Superpowers remains the skills framework. (Assistant's
  call, following `docs/rules-applicability.md`.)
- **Verification is recorded, not gated.** The documented diff is run manually
  for this cycle's evidence; a future cycle may make it a check. (Assistant's
  call: the default suite must not spawn git or network.)
- **The transition record stays.** `AGENTS.md` is the effective index;
  `docs/rules-applicability.md` remains the dated mapping and history and gains a
  dated document-budgets entry recording 400 → 150/250 and why `docs/sdd.md`
  stays untouched. No new repository-level decisions register. (Paul's decision.)
- **The glossary is product vocabulary.** Contributor-process terms (reviewer
  brief, document budget, backlog entry, pathology) are defined where they are
  used, not added to `docs/glossary.md`; the exemption is recorded beside the
  close-checklist mapping. (Paul's decision.)
- **P2.2 corrects stale references, does not rewrite P2.1 content.** `README.md`'s
  document list, `docs/domain.md`'s “planned in P2.1” rows, and `CHANGELOG.md`
  are updated because they would otherwise be wrong after this cycle.
  (Assistant's call; the PR stays small and the stacked diff shows the edits.)
- **Budgets stay prose here.** P2.2 states them in `AGENTS.md`; P2.3 owns the
  machine-readable constants and a consistency test, following the
  `scripts/repo-weight.mjs` precedent. (Assistant's call: one home, added when
  the checker exists.)
- **“Decisions table” means the per-spec `## Decisions` section.** `AGENTS.md`
  points there; no repository-wide table is created. (Assistant's call, matching
  both existing specs.)
- **The P2.3 gate is named, not linked.** `AGENTS.md` says the cap/lifecycle
  check arrives in P2.3; its link is added when the file exists. (Assistant's
  call; follows Paul's “links only what exists” decision.)
- **Skill discovery evidence is split.** P2.2 records a structural check (valid
  frontmatter, name, no collision); the interactive Pi demonstration belongs to
  P2.6, and the PR says so explicitly. (Assistant's call: a scratch Pi session
  needs model/auth and would exceed this cycle.)
- **`AGENTS.md` caps itself at 80 lines.** If it grows past that, content moves
  to a linked document. (Assistant's call, to keep the always-loaded file small.)

## Content outline for `AGENTS.md`

1. What this repository is, the port status, and that the preserved files are
   evidence, not the active rules.
2. Read order: `BRIEF.md` → `docs/rules-applicability.md` → `docs/sdd.md`, then
   `ROADMAP.md`; precedence and exclusions.
3. The cycle and where current work lives; human approval before implementation.
4. Document budgets and the reviewer brief; where rationale goes.
5. Default checks and the model/network/subprocess prohibition.
6. Hard boundaries: no contributor skills in the subject worker, preserved
   files untouched, runtime code belongs to its later cycle.
7. Glossary scope: product terms only; process terms are defined where used.
8. Links: glossary, domain, setup, roadmap, backlog, pathologies, plans, and the
   dated budget mapping in `docs/rules-applicability.md`.

## Left to the builder

- Exact wording and ordering within the 80-line cap; the link list's grouping.
- The wrapper skill's name and description wording, provided it routes to
  `AGENTS.md` and `docs/sdd.md` and repeats no process text.
- The backlog and pathology entry templates and their field names.
- Whether the provenance verification output is summarised in the PR only or
  also in a short dated note beside `docs/provenance/README.md` (which stays
  unedited).
- How P2.2's roadmap status records the stack and the PR.
