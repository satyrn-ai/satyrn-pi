# P2.3 cap, lifecycle and evidence gates: design

## Reviewer brief

**Intent:** the document budgets, plan lifecycle and evidence wording are enforced
by model-free tests, so a reviewer no longer has to catch them by eye.

**Decisions:** budgets live in `scripts/doc-budgets.mjs` and `AGENTS.md` is checked
against it; the P1.2 plan gains its missing front matter and the P2.1 spec gains
a reviewer brief; every archive already needs a terminal `## Result`; the wording
scan covers research notes only, where model-run claims are recorded.

**Non-goals:** CI wiring, vocabulary checks (P2.4), the tripwire and import check
(P2.5), the discovery demonstration (P2.6), runtime code.

**Verification:** each check fails on a fixture and on a planted repository
violation before it passes; both default suites stay green and subprocess-free.

## Intent and why

P2.2 set the budgets and the lifecycle rules in `AGENTS.md`, but nothing enforces
them. A budget without a checker is advice, and the evidence-wording rule in
`docs/sdd.md` (a page stating `n = 1` may not say “null”, “void” or “separated”)
has never had its test in this repository. P2.3 makes all three executable in the
default Node suite.

## Goals

- `scripts/doc-budgets.mjs`: the numbers in one place, imported by the checks and
  by a test that verifies `AGENTS.md` states the same four budgets.
- Cap checks: roadmap lines and cells, backlog entries and empty backlog, spec
  and plan lines, reviewer brief, plan fenced share, `AGENTS.md` lines.
- Lifecycle checks: plan front matter, active plans without `## Result`, archived
  plans with a terminal `## Result`.
- Evidence-wording check over research notes: `n = 1` and a banned claim in
the same section.
- Corrections so the gates pass: P1.2's plan front matter, P2.1's reviewer brief.
- Each check demonstrated failing first on a fixture, then on a planted
  repository violation that is reverted.

## Non-goals

- CI configuration or GitHub Actions.
- The vocabulary budget and retired-term check (P2.4).
- The default-test tripwire and one-way import check (P2.5).
- The discovery demonstration and phase close (P2.6).
- Runtime code, model calls, network or subprocesses in the default suite.
- Editing archived plans or preserved files.

## Anti-goals

- Checks that spawn `git`, a shell or a model.
- A checker that edits documents; it reports.
- A blanket exemption list that hides future violations.
- Requiring a non-empty backlog or a minimum roadmap row count.
- Weakening the preserved wording rule to make a document pass.

## Constraints

- Branch `p2.3/gates`, stacked on `p2.2/rules-index`; one PR into that branch.
- `docs/sdd.md` and `docs/provenance/` stay byte-for-byte; archived plans are
  never edited.
- Default suites remain model-, network- and subprocess-free; filesystem reads
  only.
- Budgets tighten the preserved 400-line caps for new work as recorded in
  `docs/rules-applicability.md`.

## Decisions

- **Budgets are constants.** `scripts/doc-budgets.mjs` exports `BUDGET`
  (`spec: 150, plan: 250, brief: 30, agents: 80, roadmap: 400, ships: 900,
  excludes: 900, status: 1000, backlogEntry: 1200, planFenced: 0.25`). A test
  asserts `AGENTS.md` states the four numbers (Assistant, per P2.2's plan).
- **P1.2's plan gets front matter.** The active
  `2026-11-17-p1.2-vocabulary-implementation.md` has none; P2.3 adds the six
  required lines as a correction rather than grandfathering it. (Paul's decision.)
- **P2.1's spec gets a reviewer brief.** The spec predates the rule but shares the
  rule's date; a short brief is added, keeping it within 150 lines. (Assistant.)
- **No archive exemptions.** The archived P1.1 plan already ends with a terminal
  `## Result`, so every archive must carry one; an earlier exception was removed
  when the review showed it was dead code. (Review fix.)
- **The wording rule covers research notes only.** `n` counts model trials, not
  feature cycles; the rule applies where run claims are recorded, so the scan is
  `docs/superpowers/research/**`. Process documents can quote the rule, and the
  preserved `docs/sdd.md` is out of scope automatically. (Paul's decision, after
  the broad scope tripped this spec.)
- **Sections bound the wording rule.** Split on `## ` headings; a research-note
  section that states `n = 1` and uses `null`, `void` or `separated`
  (case-insensitive whole words) fails. This lets one note report an `n = 1`
  presence and an `n = 3` comparison honestly. (Assistant, approved by Paul.)
- **Empty records are valid.** The backlog check accepts zero entries and requires
  a reopen condition only when an entry exists. (Assistant, following acceptance.)
- **Planted violations are evidence, not commits.** The demonstration edits a
  scoped file, runs the suite, sees the failure, reverts, and records the result
  in the plan. (Assistant.)
- **The checker reports, never edits.** It returns findings with file, line or
  heading, and the failing term or rule. (Assistant.)

## Check definitions

- **Caps:** `ROADMAP.md` ≤ 400 lines; each `| **` row's Ships and Excludes cells
  ≤ 900 chars and Status ≤ 1000; every active plan ≤ 250 lines and ≤ 25% fenced;
  every spec ≤ 150 lines and, if it has `## Reviewer brief`, that section ≤ 30
  lines; `AGENTS.md` ≤ 80 lines; backlog entries ≤ 1200 chars.
- **Lifecycle:** every plan file has front matter with `phase`, `feature_cycle`,
  `cycle`, `lifecycle`; active directory requires `lifecycle: active` and no
  `## Result`; archive requires `lifecycle: closed` or `superseded` and a terminal
  `## Result`.
- **Wording:** scan `docs/superpowers/research/**` only. Split each note on `## `
  headings; a section matching `n\s*=\s*1` (so `n = 1` and `n=1`, not `n >= 1`)
  that also contains a whole-word `null`, `void` or `separated`
  (case-insensitive) is a finding.

## Left to the builder

- Module and function names, fixtures, and the shape of a finding.
- Exact regex for front matter and the `## Result` terminal rule (last `##`-level
  section, or any `## Result`); the spec requires “terminal”.
- Whether caps and lifecycle share one test file or one per rule.
- How the `AGENTS.md` consistency test locates the four numbers in prose.
- How the planted violations are recorded in the plan's evidence.

## Verification

- `npm test` passes with the existing 24 tests plus the new gate tests;
  `uv run pytest` still passes; `git diff --check` clean.
- Each gate test is shown failing before its implementation, and each gate is
  shown failing on a planted repository violation that is then reverted.
- `AGENTS.md`, the P2.1 spec, and the P1.2 plan pass the new checks.
- Preserved files are unchanged; no test spawns a process or reaches the network.
