# P2.4 vocabulary budget and retired-term check: design

## Reviewer brief

**Intent:** the product glossary stays within its 25-term budget, and retired
names do not leak back into product-facing documentation.

**Decisions:** the scan covers product-facing docs only — `README.md`,
`AGENTS.md`, `BACKLOG.md` and the `docs/**` tree minus the process records —
with contributor and source-mapping records excluded by path; fenced code is
skipped; plurals match (`stages`) while `staging` does not; exemptions need a
reason and never apply to headings; the four retired-term hits in
`docs/domain.md` are reworded rather than exempted.

**Non-goals:** the tripwire and import check (P2.5), the discovery demonstration
(P2.6), editing `BRIEF.md`, `ROADMAP.md`, `docs/sdd.md`,
`docs/rules-applicability.md` beyond one dated mapping, or any runtime code.

**Verification:** glossary ≤ 25 `###` entries and states 25; the scoped docs
return no findings; fixtures prove prose, exemption, heading and budget failures;
one planted violation is seen failing and reverted.

## Intent and why

P1.2 agreed the vocabulary and a 25-term glossary budget, and its plan specified
a retired-terms check with point-of-use exemptions. P2.3 enforced document sizes
and plan lifecycle but not vocabulary. P2.4 makes the budget and the retired
names executable in the same default suite.

## Goals

- `scripts/retired-terms.mjs`: the retired terms, their replacements and the
  product-facing scope in one data module.
- `scripts/vocabulary-checks.mjs`: retired-term findings and the glossary budget
  check, both pure functions over text.
- `BUDGET.glossary = 25` in `scripts/doc-budgets.mjs`; a test that the glossary
  introduction states the same number.
- Reword the four ordinary-English or source-mapping hits in `docs/domain.md`
  (“Stage”, “grading stage”, “checkout-local ladder”) so the product docs pass
  without exemptions.
- Add the checks to `npm run check:docs` and the default suite.
- A dated scope mapping in `docs/rules-applicability.md`.
- One planted retired-term violation, seen failing and reverted.

## Non-goals

- The default-test tripwire and one-way import check (P2.5).
- The discovery demonstration and phase close (P2.6).
- A blanket ban on ordinary English or on source quotations.
- Editing documents from the checker.
- Hand-maintained exemption lists; exemptions live at the point of use.
- Editing `BRIEF.md`, `docs/sdd.md` or `docs/provenance/`, beyond the one dated
  mapping in `docs/rules-applicability.md`. P2.4's own roadmap status, `## Now`,
  and the `AGENTS.md` check sentence are updated as usual.

## Anti-goals

- A scope so wide that preserved or contributor records need exemptions.
- A check that rewrites text or spawns a process.
- Counting aliases or prose as glossary terms.
- Treating `screen`, `arm` or `redispatch` as retired; P1.2 retained them.

## Constraints

- Branch `p2.4/vocabulary`, stacked on `p2.3/gates`; one PR into that branch.
- Default suites stay model-, network- and subprocess-free.
- Exemptions use `<!-- vocabulary: <reason> -->` on the same line or the line
  before; a heading always fails, exemption or not.
- The glossary budget is 25 `###` entries; aliases do not count.
- Preserved files stay byte-for-byte.

## Decisions

- **Narrow scope, as a category.** Include `README.md`, `AGENTS.md`,
  `BACKLOG.md`, and `docs/**/*.md`; exclude `docs/sdd.md`,
  `docs/rules-applicability.md`, `docs/superpowers/**` and
  `docs/provenance/**`, plus root `BRIEF.md` and `ROADMAP.md`. Contributor and
  source-mapping records legitimately discuss the old names, and future site
  sources under `docs/` are covered without another edit. Recorded as a dated
  mapping in `rules-applicability.md`. (Paul's decision; category form is the
  assistant's call.)
- **Fenced code is skipped.** Code and shell blocks are not product prose; P1.2
  already excluded code paths. A fence containing a retired term passes.
  (Assistant.)
- **Inflected forms match.** Terms match whole-word plurals (`stages`,
  `ladders`, `rungs`, `tiers`, `floors`, `remedy units`) but not longer words
  such as `staging`. P1.2 counted inflections and quoted “rungs”. (Assistant.)
- **Exemptions need a reason.** `<!-- vocabulary: <reason> -->` must have a
  non-empty reason; the reason may name the term, and the exempt line is not
  scanned. Same-line and preceding-line comments are both legal; headings are
  never exempt. (Assistant, from P1.2.)
- **Roadmap and AGENTS stay accurate.** The cycle updates its roadmap row,
  `## Now`, and the `AGENTS.md` check sentence that lists what `check:docs`
  covers. (Assistant.)
- **Six retired terms.** `stage`, `floor`, `remedy unit`, `tier`, `ladder`,
  `rung`, each with a replacement or source-only guidance from the P1.2 plan.
  `screen`, `arm` and `redispatch` stay retained. (Assistant, from P1.2.)
- **Reword, then exempt only if needed.** The four `docs/domain.md` hits are
  ordinary English or source mapping and are reworded (`Stage` → `Step`,
  “grading stage” → “grading step”, “checkout-local ladder” → “checkout-local
  source tree”); the exemption mechanism still ships for future cases.
  (Assistant.)
- **Headings are never exempt.** A retired term in a heading fails even when
  the body carries an exemption, because headings drive site navigation. (P1.2
  plan.)
- **Budget lives with the other numbers.** `BUDGET.glossary = 25` in
  `scripts/doc-budgets.mjs`; the glossary introduction must state 25.
  (Assistant.)
- **Same CLI.** `npm run check:docs` collects vocabulary findings with the P2.3
  checks; tests import the functions directly. (Assistant.)
- **Planted evidence, not a commit.** One scoped page gains a retired term, the
  suite is seen failing, and the file is reverted. (Assistant.)
- **The check reports.** Findings carry path, line, term and guidance; nothing
  is edited. (P1.2 plan.)

## Check definitions

- **Retired terms:** for each scoped page, outside CommonMark fences (up to
  three leading spaces, backtick or tilde, closing at least as long), match each
  term and its plural as case-insensitive whole words. Skip a line with a
  non-empty `<!-- vocabulary: reason -->` comment, or whose preceding line
  carries one. A heading (`^ {0,3}#{1,6}[ \t]`) always fails. Report path, line,
  term and guidance. The glossary count uses the same fence rule.
- **Glossary budget:** count `^### ` headings in `docs/glossary.md`; more than
  `BUDGET.glossary` is a finding. Aliases (`<!-- zensical-glossary-aliases: -->`)
  do not count.
- **Scope:** the include list above, expanded against the filesystem; missing
  files and directories are skipped.

## Left to the builder

- Exact module and function names, the retired-term data shape and the finding
  text.
- Whether the glossary budget test lives with the vocabulary tests or the cap
  tests.
- How the reworded `docs/domain.md` rows read.
- Where the dated scope mapping sits in `rules-applicability.md`.
- How the planted violation is recorded in the plan evidence.

## Verification

- `npm run check:docs` reports no findings; `npm test` and `uv run pytest` pass.
- Fixtures prove: a retired term in prose fails; a plural fails; `staging`
  passes; a fenced block passes; same-line and preceding-line exemptions pass;
  an empty reason fails; a heading fails despite an exemption; a glossary over
  25 entries fails.
- The scoped docs pass without exemptions after the four rewords.
- One planted violation fails the suite and is reverted.
- Preserved files and excluded documents are untouched.
